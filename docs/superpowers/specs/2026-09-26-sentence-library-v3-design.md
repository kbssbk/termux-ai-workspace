# 문장 라이브러리 V3 — 장기 사용형 출판물 독서 기록 앱 설계

작성일: 2026-09-26
브랜치: `sentence-library-v3-redesign`
Canva UI/UX 컨셉: `DAHWQc2ntZU`

## 1. 제품 목적

문장 라이브러리 V3는 특정 앱에 사용자의 독서 기록을 가두지 않으면서, 출판물을 읽고 진행상황과 기억할 문장을 장기간 정리하는 개인용 Android 앱이다.

핵심 사용 흐름은 다음과 같다.

1. 출판물/호수/기사를 등록하거나 공식 목차에서 불러온다.
2. 기사별 독서 상태와 진행률을 기록한다.
3. 읽는 도중 기억할 문장, 태그, 위치, 메모를 빠르게 저장한다.
4. 기사 단위로 요약, 느낀점, 적용점을 정리한다.
5. 전체 독서 진행상황을 대시보드에서 확인한다.
6. 원하는 시점에 기사 단위 또는 전체 기록을 A4 문서와 개방형 데이터 파일로 내보낸다.

앱은 기록을 입력하고 관리하는 도구이며, 데이터의 최종 소유자는 사용자다.

## 2. 설계 원칙

- **휴대폰 로컬이 원본**: 인터넷이 없어도 모든 핵심 기능이 동작한다.
- **데이터는 앱보다 오래 살아남기**: JSON/CSV는 앱 없이도 읽을 수 있는 탈출구다.
- **한 번 입력하면 다시 입력하지 않기**: 기사/호수/출판물 정보는 재사용한다.
- **핵심 작업은 2~3탭 이내**: 이어 읽기, 진행률 수정, 문장 추가가 가장 빠른 경로를 가진다.
- **기본은 단순하게, 고급은 열어두기**: 초보 사용자는 기본값만으로 사용하고, 고급 설정에서 자유롭게 확장한다.
- **잘못 설정해도 되돌릴 수 있게**: 설정 스냅샷, 최근 변경 되돌리기, 무결성 검사, 안전 모드를 제공한다.
- **공식 자료와 개인 기록 분리**: 외부에서 갱신되는 목차 데이터가 개인 진행률/메모를 덮어쓰지 않는다.
- **출력 품질은 별도 문서 엔진으로**: 앱 화면을 캡처하는 방식이 아니라 저장 데이터를 A4 템플릿에 렌더링한다.

## 3. 권장 기술 구조

### 3.1 Android 앱

V3는 기존 WebView 중심 구조에서 **Kotlin + Jetpack Compose + Room(SQLite)** 기반의 네이티브 앱으로 전환한다.

이유:

- 장기 유지보수에 유리함
- Android 터치/뒤로가기/공유/파일 저장/인쇄 API와 자연스럽게 통합 가능
- Room의 명시적인 스키마 버전과 마이그레이션으로 수년간 데이터를 안전하게 유지 가능
- WebView `file://` CORS 및 브리지 의존성을 제거 가능
- 접근성, 화면 크기 대응, 키보드/포커스 처리 개선

### 3.2 로컬 원본 DB

Room(SQLite)이 원본 데이터 저장소다. 주요 엔터티:

- `Publication` — 출판물 종류/사용자 정의 출판물
- `Issue` — 연도, 호수, 공식 출처 메타데이터
- `Article` — 기사 제목, 순서, 진행 상태, 진행률, 요약/느낀점/적용점
- `Quote` — 저장 문장, 위치, 메모
- `Tag` — 사용자 정의 태그
- `QuoteTagCrossRef` — 문장-태그 다대다
- `StatusDefinition` — 사용자 정의 상태
- `CustomFieldDefinition` — 사용자 정의 필드 정의
- `CustomFieldValue` — 기사/문장별 사용자 필드 값
- `AppPreference` — 화면/정렬/대시보드 설정
- `RecoverySnapshot` — 설정/메타데이터 복구 지점
- `SyncMetadata` — JW.ORG 목차 갱신 상태

개인 기록과 공식 목차를 논리적으로 분리하여 동기화가 개인 데이터를 덮어쓰지 않도록 한다.

## 4. 기존 데이터 마이그레이션

V3 첫 실행 시 다음 경로를 지원한다.

1. V2 JSON 백업 파일 가져오기
2. `sentence_library_android_local_v1` 구조 인식
3. 호수/기사/진행률/문장/태그를 V3 Room 스키마로 변환
4. 변환 전 자동 안전 백업 생성
5. 변환 결과 요약 표시
6. 실패 항목은 별도 오류 리포트로 보존

마이그레이션은 한 번 실행해도 원본 JSON 파일을 수정하지 않는다.

## 5. 상태 시스템

기본 상태:

- 미완 — 기본 0%
- 진행중 — 기본 25%, 사용자가 1~99% 조정
- 완성 — 기본 100%, 완료로 집계

고급 설정에서 상태를 추가/수정/순서 변경할 수 있다.

상태 정의 속성:

- 이름
- 아이콘
- 표시 순서
- 기본 진행률
- 진행률 직접 조정 허용 여부
- 완료 상태로 집계할지 여부
- 대시보드 표시 여부

상태 정의를 변경해도 기존 기사의 실제 진행률과 문장 기록은 삭제하지 않는다.

## 6. 태그와 사용자 정의 필드

기본 태그:

- 여호와
- 예수
- 성령
- 관계
- 도움
- 발전

사용자는 태그를 추가/이름 변경/정렬할 수 있다.

사용자 정의 필드는 선택적으로 활성화한다. 예:

- 페이지
- 항
- 중요도
- 재독 예정일
- 별점
- 사용자 텍스트 필드

기본 UI에서는 고급 필드를 숨기고 필요할 때만 펼친다.

## 7. 기사 작업공간

기사는 앱의 핵심 작업 화면이다.

상단:

- 출판물 / 연도 / 호수
- 기사 제목
- 공식 출처 링크
- 상태
- 진행률

중앙:

- 진행률 슬라이더
- 저장 문장 목록
- 빠른 문장 추가
- 태그 필터

확장 섹션:

- 기사 요약
- 느낀점
- 적용점
- 사용자 정의 필드

문장 입력에는 다음 필드가 있다.

- 문장 본문
- 페이지/항 등 위치
- 태그
- 개인 메모
- 생성일/수정일

문장 저장은 기사 화면에서 1~2탭 내에 시작할 수 있어야 한다.

## 8. 내비게이션 / UI 구조

하단 탭은 최대 4개로 제한한다.

1. **홈** — 이어 읽기, 빠른 문장 추가, 최근 활동
2. **출판물** — 연도/호수/기사 탐색, 검색/필터/정렬
3. **대시보드** — 전체 및 연도별 진행현황
4. **검색** — 기사, 문장, 태그, 메모 통합 검색

설정과 내보내기는 상단 메뉴 또는 프로필/도구 버튼에서 접근한다.

### 홈

가장 중요한 것은 `이어 읽기`다. 통계는 최소화한다.

- 이어 읽기
- 최근 수정 기사
- 빠른 문장 추가
- 오늘/이번 주 활동
- 최근 호수

### 출판물

- 연도 선택
- 출판물 필터
- 상태 필터
- 정렬 기준
- 카드/컴팩트 목록 보기 전환
- 호수 카드 전체가 탭 가능
- 호수 펼침 또는 상세 화면 이동

### 대시보드

Google Drive의 `파수대 깨어라` 대시보드 구조를 참고하되 앱 데이터에서 실시간 계산한다.

- 전체 진행률
- 전체 기사
- 완료
- 진행중
- 미완
- 연도별 진행률
- 최근 활동
- 예상 완료 시점

연도 행을 탭하면 해당 연도로 이동한다.

## 10. 공식 JW.ORG 데이터

공식 자료는 `jw.org`, `wol.jw.org`, 공식 JW CDN만 사용한다.

V3에서는 네이티브 네트워크 계층을 사용한다.

원칙:

- 공식 목차는 갱신 가능한 참조 데이터
- 개인 진행률, 문장, 메모는 로컬 사용자 데이터
- 제목 변경/공식 링크 갱신 시 사용자 데이터 보존
- 성공 항목 캐시
- 실패 항목만 재시도
- 요청 제한 및 백오프
- 실패 이유 기록

역사적 출판물 이름은 강제로 `파수대—연구용`으로 바꾸지 않고 공식 사이트에 나타난 명칭을 저장한다.

## 11. 내보내기

내보내기는 네 가지 목적을 분리한다.

### PDF

A4 인쇄/보관용.

#### 기사별 PDF

- 출판물 / 연도 / 호수
- 기사 제목
- 진행 상태 및 진행률
- 기사 요약
- 느낀점
- 적용점
- 저장 문장
- 문장별 위치
- 문장별 태그
- 문장별 메모
- 출력일
- 선택적 쪽번호/머리글

#### 전체 PDF

연도 → 호수 → 기사 순으로 구조화한다. 긴 데이터는 자동 페이지 분할한다.

### DOCX

PDF와 유사한 문서 구조를 제공하되 사용자가 Word/Google Docs에서 후편집할 수 있도록 한다.

### CSV

사람과 스프레드시트가 다루기 쉬운 표준 데이터 파일로 다음 테이블을 각각 내보낸다.

- publications.csv
- issues.csv
- articles.csv
- quotes.csv
- tags.csv
- quote_tags.csv
- custom_fields.csv

### JSON

전체 데이터 + 설정 + 스키마 버전 + 내보내기 버전을 포함한 완전 백업 포맷이다.

JSON 스키마 문서를 저장소에 함께 둬 다른 앱에서도 구현 가능하게 한다.

## 12. 앱 종속 탈피

사용자는 앱이 없어져도 다음을 할 수 있어야 한다.

- JSON을 일반 텍스트 편집기/다른 프로그램에서 읽기
- CSV를 Google Sheets/Excel로 열기
- PDF를 인쇄/보관하기
- DOCX를 편집하기
- 다른 앱 개발자가 공개된 JSON 스키마를 이용해 가져오기 구현하기

내보내기 데이터에 내부 Android 경로나 기기 고유 ID를 필수값으로 사용하지 않는다.

## 13. 복구 전략

앱은 위험한 작업 전에 자동 복구 지점을 만든다.

자동 스냅샷 대상:

- 대량 가져오기
- 상태 정의 변경
- 태그 대량 변경
- 사용자 필드 구조 변경
- 데이터 병합
- 전체 동기화 갱신

복구 센터에서는:

- 최근 변경 되돌리기
- 설정만 복원
- 특정 엔터티만 복원
- 전체 복원
- 무결성 검사 결과 보기

을 지원한다.

## 14. 설치/업데이트 전략

장기 사용을 위해 **안정적인 단일 서명키**를 사용한다. GitHub Actions의 매 실행마다 달라질 수 있는 기본 debug 서명에 의존하지 않는다.

릴리스 산출물:

- 서명된 APK
- SHA-256 체크섬
- 버전명/버전코드
- 마이그레이션 안내
- JSON 스키마 버전

기존 앱과 서명이 다를 경우 기존 앱에서 JSON 백업 후 V3 설치 → 가져오기 절차를 사용한다.

## 15. Canva의 역할

Canva는 앱 구현 플랫폼이 아니라 **UI/UX 설계 도구**로 사용한다.

Canva 컨셉 보드를 다음 구현 결정에 반영한다.

- 시각적 위계
- 카드 밀도
- 간격
- 핵심 행동 버튼의 우선순위
- 대시보드 정보 구조
- A4 출력 레이아웃

실제 Android UI는 Jetpack Compose로 구현한다.

## 17. 성공 기준

- 기존 V2 JSON 기록을 손실 없이 가져올 수 있다.
- 오프라인에서 기록/검색/대시보드/내보내기가 가능하다.
- 진행률 수정 및 문장 추가가 기사 화면에서 빠르게 가능하다.
- 상태/태그/필드를 사용자가 변경해도 데이터 무결성이 유지된다.
- 위험한 설정 변경을 복구할 수 있다.
- 기사별 PDF가 A4에서 잘리지 않고 읽기 좋게 출력된다.
- 전체 데이터를 JSON/CSV로 내보내 앱 없이 확인할 수 있다.
- JW.ORG 목차 갱신이 개인 진행률/메모를 덮어쓰지 않는다.
- 동일 서명키로 이후 버전을 업데이트 설치할 수 있다.
